# KOS3 accelerometer services

Набор фоновых C++17-сервисов для трёх узлов: узел A эмулирует акселерометр, Linux-сервер валидирует поток и отбрасывает подряд идущие дубликаты, узел B вычисляет модуль ускорения и возвращает результат через сервер обратно на узел A.

## Архитектура

Используется базовый уровень: TCP/IPv4 + JSON Lines.

По умолчанию сервер открывает три TCP-порта:

| Порт | Канал | Назначение |
| --- | --- | --- |
| `5000` | A -> Server | поток `{timestamp,x,y,z}` от эмулятора акселерометра |
| `5001` | Server <-> B | пересылка валидированных данных на B и получение `{timestamp,module}` обратно |
| `5002` | Server -> A | пересылка рассчитанного модуля на A |

Узел A создаёт два исходящих соединения: канал отправки данных на порт `5000` и канал приёма результатов с порта `5002`. Узел B использует одно двунаправленное соединение с портом `5001`.

## Форматы сообщений

Данные акселерометра:

```json
{"timestamp":1712938123456,"x":0.123,"y":9.807,"z":0.045}
```

Ответ с модулем ускорения:

```json
{"timestamp":1712938123456,"module":9.808}
```

Каждое сообщение завершается символом новой строки. Сервер сравнивает только `x`, `y`, `z` текущего пакета с предыдущим принятым пакетом и отбрасывает подряд идущий дубль после округления до 3 знаков после запятой.

## Сборка на Ubuntu 22.04

```bash
sudo apt-get update
sudo apt-get install -y build-essential cmake
cmake -S . -B build
cmake --build build -j
```

После сборки появляются исполняемые файлы:

- `build/accel_server`
- `build/accel_node_a`
- `build/accel_node_b`

## Запуск в терминалах

Терминал 1:

```bash
./build/accel_server --accel-port 5000 --b-port 5001 --result-port 5002
```

Терминал 2:

```bash
./build/accel_node_b --server-host 127.0.0.1 --server-port 5001
```

Терминал 3:

```bash
./build/accel_node_a --server-host 127.0.0.1 --accel-port 5000 --result-port 5002 --module-file accel/module.log
```

Узел A генерирует синусоидальный сигнал с небольшим шумом с частотой около 50 Гц. Результаты пишутся в CSV-подобный файл `accel/module.log` в формате:

```text
timestamp,module
```

## Демон-режим и systemd

У каждого бинарного файла есть флаг `--daemon`, но предпочтительнее использовать unit-файлы systemd из каталога `systemd/`.

Установка:

```bash
cmake --install build --prefix /usr/local
sudo mkdir -p /var/log/kos3
sudo cp systemd/*.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now accel-server.service accel-node-b.service accel-node-a.service
```

Логи сервисов можно смотреть через `journalctl` и файлы, указанные в `--log-file`.

## Основные параметры

### `accel_server`

- `--accel-port <port>` — порт канала A -> Server, по умолчанию `5000`.
- `--b-port <port>` — порт канала Server <-> B, по умолчанию `5001`.
- `--result-port <port>` — порт канала Server -> A, по умолчанию `5002`.
- `--duplicate-decimals <n>` — точность сравнения дубликатов, по умолчанию `3`.
- `--log-file <path>` — файл журнала.
- `--daemon` — двойной fork и работа в фоне.

### `accel_node_a`

- `--server-host <IPv4>` — адрес сервера, по умолчанию `127.0.0.1`.
- `--accel-port <port>` — порт отправки акселерометра, по умолчанию `5000`.
- `--result-port <port>` — порт приёма модулей, по умолчанию `5002`.
- `--frequency-hz <n>` — частота генерации, по умолчанию `50`.
- `--module-file <path>` — файл результатов, по умолчанию `accel/module.log`.
- `--log-file <path>` — файл журнала.
- `--daemon` — работа в фоне.

### `accel_node_b`

- `--server-host <IPv4>` — адрес сервера, по умолчанию `127.0.0.1`.
- `--server-port <port>` — порт B-канала, по умолчанию `5001`.
- `--log-file <path>` — файл журнала.
- `--daemon` — работа в фоне.

## Безопасность и устойчивость

- Все сокеты используют IPv4/TCP и `SO_REUSEADDR` для удобного перезапуска.
- `SIGPIPE` игнорируется, ошибки `send/recv` логируются.
- При потере соединения узлы A и B автоматически переподключаются.
- systemd unit-файлы включают `NoNewPrivileges` и ограничивают временную/системную область там, где это не мешает работе.
- Протокол ограничивает максимальную длину строки 4096 байтами.
